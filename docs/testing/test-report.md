## Backend test coverage

Database-specific verification: registration against the configured unreachable PostgreSQL service initially had no response within an 8-second bound. With the new engine settings, the same endpoint returns HTTP 503 `Database unavailable` in 3.12 seconds. The PostgreSQL engine uses a three-second connect timeout; the development-only `localhost` case pins one loopback address so dual-stack retries do not multiply that wait. Alembic revisions 0001–0005 pass on SQLite and a fresh PostgreSQL 17 Compose database. Revision 0004 is now named `0004_nullable_category` (22 characters); the migration environment maps the previous long ID to the short one for existing SQLite databases. A new revision-length test checks every revision and parent ID is at most 32 characters. `0003_agent_status_contract` is an already released revision and was not modified in this fix; because changing a stamped migration does not rerun it, `0005_agent_status_repair` safely reapplies the legacy status normalization for databases that may have stamped an older 0003 body. The fresh PostgreSQL run used a separate new Compose project and volume; the existing PostgreSQL volume was not altered.

The first full backend test run in this checkout yielded 155 passed and 3 failed because three workflow tests followed `.env`'s configured but stopped URL scanner. The tests now disable live scanner access by default; tests using scanner behavior supply fakes explicitly. The combined backend suite passed all 179 tests after the migration and admin modules were integrated.

Tests cover redaction of OTP/credentials before an LLM request, URL origin extraction, seeded category detection, weighted score thresholds, HTTPS and shortener/typosquatting heuristics, deterministic LangGraph completion/skips, registration/login/session, unauthorized access, CSRF rejection, backend and scanner rate limits, request validation, report persistence, redacted stored content, threat-intel timeout/failure handling, provider throttling and unavailable results, conflicting provider results, prompt-injection isolation, agent failure and timeout paths, seven separate agent graph nodes, separate /analyze and /reputation calls, four-state status contract, LLM provider-setup failure fallback, deterministic train/validation/test splitting, metric calculations, baseline fit, local full-pipeline evaluation, SSRF range blocking (including metadata and IPv4-mapped IPv6), legacy decimal/hex/octal IP rejection before DNS, userinfo and scheme/port rejection, mixed DNS answers, pinned-IP connections, private redirects and per-hop revalidation, redirect caps, HEAD and bounded text-only GET behavior, and request/response caps. Migration tests enforce the PostgreSQL revision-length limit, normalize an old SQLite revision alias, and exercise the agent-status forward repair; the full migration chain was also run on fresh PostgreSQL 17 through Compose. Admin tests verify non-admin 403 responses, database aggregates for every metric, first-admin password hashing, and refusal after the first admin exists. The pre-transaction and conversation tests add 62 cases: 15 scam and 15 legitimate transaction examples, plus 15 scam and 17 legitimate conversation examples. They cover UPI collect requests, advance-fee job fraud, digital arrest, credential requests, pressure escalation, identity changes, genuine bank/OTP notices, ordinary chats, and benign bill reminders. Frontend URL report tests cover unavailable, checked, rate-limited, flagged, and clean provider states, including verification badges and the not-verified-safe wording. Auth UI/service tests cover FastAPI validation detail formatting, the 15-second request timeout, client/backend field validation, and loading reset after timeout/error. Evaluation-v2 adds required author metadata, test/train exact and near-duplicate leakage checks, 2,000 stratified paired bootstrap percentile replicates for 95% CIs, and five-fold cross-validation over train+validation only; it includes a regression test that preserves the exact seed-42 test rows and the 32-row dataset. Real external provider calls and cross-user deletion/access against production data remain unverified.

## Limitations

Passing tests show only the listed cases. They do not establish production security or safety of unknown URLs. The authored evaluation set is small and illustrative; its held-out test split has only three examples per class, so its metrics are not reliable estimates of real-world performance. External LLM/provider calls were not made because credentials are not configured.
